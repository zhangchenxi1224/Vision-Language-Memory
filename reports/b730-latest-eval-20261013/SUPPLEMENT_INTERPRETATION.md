## “未见表达”“未见问题”“未训练内容”的区别

- **W*/T1：未见写入表达。** 对已训练的相同偏好换一种用户表达，问题仍为原 T1。它检验表达稳定性，不是新偏好内容泛化。
- **W0/T*：未见提问表达。** 在原用户表达生成的图上换提问方式。T* 是同一任务意图的新措辞，不代表全新的事实、任务或推理类型。
- **W*/T*：双重表达变化。** 新用户措辞生成图像，再由新问题措辞读回；仍然是那 96 条已训练内容。
- **dev90/official177：未训练内容。** 不经过教师优化或新 FM 更新，直接由固定 Writer 生成。这里的“未训练”指本项目相应训练集合，不能保证通用预训练模型从未接触过近似内容。
- **opposites16：反事实偏好。** 错配图来自对应原偏好，用改变后的正确答案评分；这些样例带有为消除歧义而增加的限定，不是严格的只改一个否定词实验，也不能单独说明原/反事实两端同时答对。

此前语义成员核验确认：latest train730 与 B730 target ID 集合完全相同；96 条诊断内容全部属于 B730 训练集，W* 均不同于原始用户文本，T* 均不同于该条旧 T1/T2/T3/O1/O2 五种问题措辞；16 条反事实均有已训练的原内容。此处的新措辞含义是本项目教师/Writer 的监督边界，不是整个基础模型的预训练曝光断言。

## 与旧 B730、aug4x3 的比较边界

**最重要的共同输入变化是固定确认语 `Understood.`。** 旧 B730 的 V0/V1 是 assistant 确认语变体，用户偏好文本没有随 V0/V1 改写；本次最新 W0 保留该原始用户文本，但统一改用 `Understood.`。因此，即使是 W0/T1，也包含旧 B730 确认语分布之外的输入条件，不能称作旧 V0/V1 原协议重跑。

历史 B730 图像的噪声与条件随机数协议、答案位置和错配供图等条件也与本次不同。旧历史成绩保留在独立列，本次标记为“B730／最新统一协议补测”。补测后与 aug4x3 的评测条件更一致，但 B730 的 4f 任务初始化、教师库、训练输入覆盖等仍不同，不能据模型间差值直接归因于数据增强。

针对表达损失，应优先在同一 96 条偏好、相同 checkpoint 和相同图像种子上计算配对差异，不能拿 train730 的总准确率直接减 diagnostics96 准确率。W0/T1 的 matched 记录可以从 train730 的这 96 条记录抽出；但 train730 与 diagnostics96 的同 topic 错配 donor 池不同，原样相减的 memory-minus-mismatch 差异还包含 donor 池变化，须披露。W*/T1 与 W*/T* 使用相同 W* 图像及诊断 donor，可以更直接比较提问表达变化。

## 控制复用与成绩验收

blank/text 与 Writer 权重无关，故从最新 aug4x3 的已完成控制中复用是合适的。复用前必须核对冻结数据、问题/选项、Reader 资产、评分代码、灰图、完整回执及原始输出哈希；保留原绑定和来源引用，不把它们记作新执行的 B730 推理。旧 B730 的控制不能直接替代本次最新控制。

每个 checkpoint 同时报告 matched、mismatch、blank、text、解析失败和完整分母，并按偏好聚合种子与位置后报告配对区间。解析失败留在分母；不依据 dev 或 official 结果挑选最好 checkpoint。终点固定为 93,440，70,080 是 B730 自有中间点，不能与 aug4x3 不存在的同名点伪配对。

若已训练内容表现提高而 dev/official 的匹配收益仍接近零，只能支持训练内容可靠性或表达稳健性改善，不能宣布新内容泛化。若瞬时 GPU 使用率低，应结合真实任务进度、生成/Reader 特征和剩余依赖判断；本次覆盖与结果解释不以伪造负载或重复评测来满足利用率目标。
