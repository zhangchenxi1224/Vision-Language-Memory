## 1. 要学的对象

历史 H_t 经过共享 Writer 被压缩为 M_t。对未来问题 q，希望
`R(M_t, q)` 保留 `R(H_t, q)` 中依赖用户偏好的有效信息。
这是一种面向任务的可更新状态，不要求复原全部对话，也不要求逐字复述偏好。

```text
上一张 RGB + 当前完整 user/assistant 交换 + 新高斯噪声
    → 共享 DreamLite Writer → 新 RGB → 保存/重新读取 → 下一次写入
                                  ↓
                       冻结 Reader + 未来问题 → 回答
```

记忆必须同时满足：跨偏好内容泛化、同图多偏好共存、覆盖与选择性清除、真实重复写入后保持、
同一固定图像回答多个未参与写入的问题。增加样本数、增加同时存储数、增加写入次数分别报告。
默认不限定图片必须自然、好看或人可读；若主要机制变成文字栅格化，须如实说明，
不能据此宣称已学得非文字视觉语义。首轮不引入人工表格布局、文本绘图目标或隐藏元数据通道。

## 2. 模型与梯度路径

| 部件 | 方案 |
|---|---|
| 起点 | PrefEval 之前的 4fbc857 Writer 权重；fresh optimizer；不继承 40 个优化后的 PrefEval latent |
| Writer | DreamLite Base，训练共享 full U-Net；所有样本使用同一个参数集合 |
| VAE / Writer 条件编码器 | 冻结权重；保留当前输出 decode 的梯度 |
| Reader | 冻结 Qwen3-VL-4B-Instruct；前向保留对图像的梯度，不能用 no_grad 包住 |
| 持久状态 | 与已验证协议相同的 1024×1024、8-bit RGB；初态为 RGB(128,128,128) |
| 推理 | 原生 Base 28 步、CFG=1、已验证 native 条件；每次从新高斯噪声开始 |
| Writer 输入 | 上一张实际 RGB 与当前原始对话交换；不带最终问题、答案、正确选项、状态标签或完整旧文本 |
| Reader 输入 | 固定最终 RGB 与问题；固定通用任务提示，不能插入隐藏偏好或类别真值提示 |

`M_t = Q8(Decode(Sample28_theta(Encode(M_(t-1)), current_exchange_t, epsilon_t)))`

source 仍然只在条件侧。不得把 source 混入生成起始噪声，或换用旧的部分加噪协议。
这次是对共享生成器施加下游答案监督，不需要每个状态先有一个“正确目标图片”。
官方 flow-matching 的目标图监督与答案 CE 是不同的目标；本方案不把后者叫作官方 FM。
旧 FM 训练器及其已验证结果继续保留，但不是新训练器的主循环。

## 3. 主损失

对当前记忆 M_t 下的监督问题集合 Q_t，使用每条回答（包括一个结束 token）的平均 NLL：

`ell_t = mean_(q,a in Q_t) [-mean_k log R(a_k | M_t, q, a_<k)]`。

训练标签在训练器中存在是正常监督，不得流入 Writer 前向。所有历史、问题及 acknowledgment
均 mask 掉，只监督最终回答。Reader 的答案前缀是 teacher forcing；效果必须另用自由生成评估。

多偏好时，每个活动类别等权，再在类别内对问题取平均。取消“新槽占一半、所有旧槽平分另一半”
的权重，避免容量扩大时旧信息的监督越来越弱。CLEARED 类别另有删除状态问题，不继续套用旧答案。

长度大于 1 的写入链采用：

`L_episode = 0.5 * ell_final + 0.5 * mean_(earlier prefixes) ell_t`。

单次写入时直接使用 ell_1。中间前缀监督提供写入、保留与更新的局部学习信号；
最终 10 轮干扰后的回答仍占一半权重。这是面向 RGB 递归的训练扩展，不能声称与论文
只对最后回答监督的纯文本训练计算图完全相同。首轮不加入额外排序损失或十几组复述模板。

实现中不能直接复用旧 `answer_mean_CE + EOS_CE` 的短答案聚合方式。
对长答案，结束符应作为一个普通受监督 token，与其余答案 token 一起平均，避免 EOS 过度加权。

## 4. 真实递归训练，但不一次反传整条长链

采用跨写入截断到 1 步、单次写入内部完整反传 28 个去噪步骤的训练。
同一 episode 中 Writer 参数固定；将各写入的梯度累积后，再按 episode batch 更新共享参数。
每次下一步读取的 source 都是该模型上一轮生成并量化的 RGB，不使用教师图替换。

```python
optimizer.zero_grad()
for episode in batch:
    memory = gray_rgb()
    for t, exchange in enumerate(episode.exchanges):
        # 前缀只作为实际 RGB 输入，不保留前一次写入的计算图。
        source = memory.detach()
        rgb_float = writer28(source, exchange, fresh_noise())
        rgb_q8 = quantize_u8_straight_through(rgb_float)
        loss = answer_token_ce(frozen_reader, rgb_q8, episode.supervision[t])
        (episode_weight(t) * loss / len(batch)).backward()
        memory = png_equivalent_rgb(rgb_q8.detach())
optimizer.step()
```

截断跨步梯度意味着这不是整条序列的精确 BPTT。中间问题监督让早期写入仍得到学习信号；
自己生成的 RGB 回放让当前更新器暴露于实际累积误差。训练成功不能只看每一步 CE，
还必须检查没有中间监督、没有优化器参与的完整推理链。

量化前向使用与现有 PNG 写入一致的 clamp、round 与 uint8 规则；反向采用 straight-through
近似。这是有偏梯度估计，不是假装量化可导。训练跨步保留的像素值与 PNG 回读相同，
正式评估逐步实际保存和读取 PNG。当前读出梯度链使用已有 tensor 图像预处理，不能转成 PIL 后
再当作仍可微。VAE 和 Reader 的权重冻结不应切断这条输入梯度链。

## 5. 数据：官方主任务加最小递归扩展

官方边界继续为 820 个训练主题样本、180 个评估主题样本。
为避免用后者调参，已在这 820 条内按既有语义组和固定哈希划出：

- Writer 训练 730 条，内部开发 90 条；同组不跨两侧。
- 从训练侧 16 个主题各选 4 个组，形成 64 条最小学习 pilot。
- 180 条官方评估样本不参与新训练、checkpoint 选择和下一轮调参。

具体 ID 在 `WRITER_IMPLEMENTATION_SPLIT.json`。
这是在官方主题边界内新增内部开发集的 DreamLite 实验，不是“仍用满官方 820 条训练”的精确复现。
历史研究已看过部分新评估主题，继续披露，不改称未受研究过程影响的密封集。

显式主任务直接复用已导出的官方 `response_to_pref`、原问题、`response_to_q` 和 10 轮上下文。
三种原始表达共享基础偏好 ID。隐式形式先作为迁移评估，不在第一轮同时扩张训练。
新训练输入不传 SET/RETAIN/CLEAR 真值标签给 Writer；操作发生与否要从当前原始对话理解。

一条原问题不足以证明图像支持未来多种用途。多偏好阶段为训练侧偏好增加少量真正不同的
应用问题：每个偏好最多 2 个训练问题，内容需要应用同一约束，而不只是复述同一句问题。
补充目标由冻结文本教师在完整历史 + Reminder 下离线生成，保存教师身份和输出；
这些补充样本明确标记为 DreamLite 扩展，不伪称官方发布数据。
新组合/覆盖/清除时，必须根据新状态重新构造正确答案；不能继续沿用覆盖前的回答。
教师失败保留在构造记录，不能静默挑选容易成功的状态后缩小评估分母。

同类偏好的反事实对使用相同问题、不同约束及相应答案，让答案必须依赖记忆内容。
CLEAR 后分别检查被删类别是否仍错误沿用旧限制、未删类别是否保持；其标准与普通应用题分开。
线上 Writer 永远不接触生成训练目标所用的完整文本历史或状态表。

## 6. 一个模型，三个连续学习阶段

下列为首轮有限预算；按结果迭代，不承诺这些步数必然收敛。阶段通过后沿用同一个共享 Writer，
不并行扩展为多个新模型架构。每阶段保存终点和内部开发最优点。

| 阶段 | 数据与任务 | 首轮预算 | 要回答的问题 |
|---|---|---|---|
| A：学习视觉写入 | 64 条训练偏好，灰图 → 一次写入 → 原问题回答 | 200 个 optimizer updates，effective batch=4 episodes | 共享 Writer 是否能把新偏好变成冻结 Reader 可利用的图像？ |
| B：语义扩容和真实保持 | 全 730 条训练样本，每条 1 次偏好写入 + 10 次干扰写入 | 2 个 episode passes；共 1,460 episodes / 16,060 次真实写入 | 对未训练偏好及干扰后的状态能否工作？ |
| C：同时存储和选择性更新 | 固定 256 条训练链，128 条两偏好、128 条四偏好；覆盖、清除和无关交换 | 最多 2 passes；每条最多 16 次写入，至多 8,192 次写入 | 四个槽的绑定、局部更新及其余槽保留能否同时成立？ |

阶段 B 的主条件为官方 10 个干扰交换；中间前缀用于训练监督，评估另报 0/5/10。
阶段 C 所有底层偏好来自 730 条训练侧，开发组合全部来自 90 条内部开发侧。
四偏好容量在四个仍然活动的槽上评估；清除后仅剩三个活动槽的状态不能混入“四活动槽容量”。
增加 50/70 次写入的长链只在基本能力通过后做长度外推，不先为长链扩张训练预算。

先用同一冻结 Reader 跑完整文本与空图参照，帮助辨别任务本身的读出难度。
文本参照不是数学上的性能上界。所有参照与 RGB 分支共享问题、生成预算和判分设置。
原始生成任务按官方 300 token 配置执行；不得沿用旧复述诊断的 32 token 上限。
更长输出若另行测量，要作为单独条件，不能替换官方条件分数。

训练建议初值：full U-Net AdamW，lr=1e-6，betas=(.9,.999)，weight_decay=0，
grad_clip=1，effective batch=4 episodes；VAE/Writer 保持已有 FP32 协议，Reader 使用既有精度。
先采用 activation checkpointing、`use_reentrant=False`，不减少 28 步或分辨率换取表面成功。
这些是保守起始值，不是已验证最优超参数。每次比较记录有效写入数、Reader 调用数及实际 GPU 小时。

## 8. 什么证据才支持“训练出了视觉记忆”

最终固定模型，不再优化任何测试状态。每张最终 PNG 连续回答多个问题，不再调用 Writer。
至少同时报告：

1. 官方生成偏好遵循、官方 MCQ；逐字恢复继续作为诊断，不充当主要成功定义。
2. 730→90 内部新内容与 180 官方主题外评估，区别训练样本和研究过程的历史暴露。
3. 一、二、四活动偏好下的逐项成功率，以及所有活动项都正确的整状态成功率。
4. 覆盖的新值生效、旧值失效；清除的约束失效；未改动槽的保持；0/5/10 次真实后续写入。
5. 同问题下换为空图、另一张同类但偏好互斥的记忆图，结果是否按记忆变化；反事实对须在语义上
   确实改变正确回答，不能随便换一个兼容偏好就要求答案变化。另用新的应用问题
   排除只缓存训练回答。少量固定随机种子复测稳定性，不从多个种子挑最佳图。

官方生成检查保留原四类错误定义。使用原 evaluator 才报告对应官方配置；若执行时更换 judge，
须明确标注并对全部比较使用同一个配置，不冒充官方结果。所有截断和不合格式输出保留。

建议预先采用的“首个可用版本”目标（工程验收线，不是论文结论）：

- 固定评估集生成偏好遵循达到 80%，且至少达到对应文本参照的 90%；
- 正确记忆相对空图/同类错误记忆的配对优势有统计支持，同时通过新应用问题；
- 10 次真实干扰写入后，偏好遵循较刚写入下降不超过 5 个百分点；
- 四活动槽整状态成功至少 70%，覆盖/清除成功且未改动项保持的联合成功至少 80%。

报告所有分母、失败原文和不确定性，不能把一个链的多次提问都当作独立样本扩大显著性。
这些新协议目标不覆盖旧 Plan12 的失败判定。若通过单偏好但四偏好失败，只能报告单偏好版本。

失败后只针对测得的瓶颈迭代：A 都不能拟合，先解决采样/梯度/可读接口；A 能拟合但新内容
失败，优先检查语义覆盖与答案捷径；单写通过而真实链失败，处理更新稳定性；四槽独有失败，
处理绑定与保持。不能在没有证据时统一归因于 latent 容量，也不能保证只换目标就必然解决。

## 9. 执行限制与当前边界

GPU 仅允许 `dl-clear-retain-h200x4-20260914`。可先用一对 GPU 放 Writer 与 Reader，
显存实测允许时另一对作为第二副本并同步共享 U-Net 梯度；不是四套独立 latent 优化器。
在执行阶段先测量 20 次真实写入的显存/耗时，再给出总 GPU 小时估算。当前没有新实例状态证据，
不承诺占用情况或训练完成时间。

本次交付是可以据此实施的算法、数据划分、代码改动清单和验收定义；上述新采样器、训练器与
GPU 实验仍未实现/执行。下一项实质性工作是打通 28 步答案梯度并启动 64 条共享 Writer pilot。

官方依据：
[PrefEval §3.7](https://arxiv.org/html/2502.09597v1#S3.SS7)、
[官方 SFT 代码](https://github.com/amazon-science/PrefEval/blob/50795054b5ff5f418d2b768a331d71e480f93331/SFT/train_sft.py)。
研究现状与原始负结果见 `../prefeval-rgb-20260917/worst-query-consolidation-results.md`。
