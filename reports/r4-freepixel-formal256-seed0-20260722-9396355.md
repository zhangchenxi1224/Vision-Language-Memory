## 二、实验协议

### 2.1 FreePixel 状态契约

- 持久状态：`float_rgb`，每个事件后解码、clamp，再作为下一事件的 RGB 输入
- 初始状态：固定中性灰 1024×1024 RGB，不可学习
- updater 输入：上一张 RGB 状态、当前可见事件文本、与答案无关的确定性采样噪声
- 禁止 updater 读取 query 或 target answer
- 无 teacher/canonical target，无 pixel/latent/feature regression，无 codebook
- Reader：Qwen3-VL-4B-Instruct，冻结，位于 `cuda:1`
- Updater：DreamLite-mobile，基础参数冻结，仅训练 U-Net LoRA rank 4，位于 `cuda:0`
- 梯度：每个 transition 只选一个 diffusion step 使用 DRTune 梯度；事件级 TBPTT horizon=1

### 2.2 正式预算

| 项目 | 固定值 |
|---|---:|
| optimizer steps | 256 |
| gradient accumulation | 8 |
| micro-transitions | 2,048 |
| SET-from-blank warmup | 32 steps / 256 micros |
| balanced phase | 224 steps / 1,792 micros |
| diffusion steps | 4 |
| learning rate | 3e-5 |
| weight decay | 1e-4 |
| global gradient clip | 1.0 |
| identity calibration | 8 train-only NOOP transitions |
| fixed eval | M0 与 final，各 8 episodes×4 choice presentations |
| checkpoint interval | 每 16 optimizer steps |

训练器禁止 early stopping、best-dev checkpoint selection 和中间 dev 选择，唯一科学 endpoint 是 step 256。

## 六、可以保留与不能宣称的结论

### 可以保留

1. R4-FreePixel 工程链路已经可运行、可复现、可审计。
2. Teacher-free recurrent RGB state 能获得有效梯度并跑满固定预算。
3. 固定 Reader endpoint 指标在 seed 0 上改善 7.02%。
4. RGB 状态保持动态、非饱和，模型快照与数据全程未漂移。
5. transition-local DRTune 将同等 256-step 实验缩短到约 1.2 小时端到端。

### 不能宣称

1. 不能由单 seed 证明改进具有统计稳定性。
2. 不能由 aggregate CE 证明 SET/OVERWRITE/CLEAR/NOOP 都改善。
3. 不能仅凭“没有 canonical teacher”证明像素中不存在文本式或符号式内部编码。
4. 不能证明 Reader 的改善一定因视觉状态内容，而非图像统计捷径或 episode-level artifact。
5. 不能把历史 R3 数值当作严格 matched baseline。

## 七、下一步建议

### P0：先用现有 endpoint 做视觉状态因果评测

无需重新训练，优先对 step-256 endpoint 做以下成对评测，并保持相同 query、choice permutation 和 Reader：

1. **正常状态**：原始 recurrent RGB state。
2. **Blank control**：在每次 Reader 查询前替换为固定灰图。
3. **Cross-episode shuffle**：把状态图随机换成其他 episode 的同 turn 状态。
4. **Within-episode temporal shuffle**：使用错误 turn 的状态。
5. **Noise/phase-scramble control**：保留像素边际统计但破坏空间结构。
6. **Updater-disabled control**：始终使用初始状态。

按 episode 配对计算 CE 差和 bootstrap 置信区间。只有正常状态稳定优于这些对照，才能支持“信息确实通过像素状态因果传递”。OCR/人类可读性可以作为诊断，但不应成为记忆成立的必要条件。

### P1：原协议复现两个额外种子

在不改变超参数、数据、预算和 checkpoint 选择规则的情况下运行 seed 1、seed 2。当前单次端到端约 1.22 小时，两次顺序运行约 2.4–2.6 小时，可落在原 3–4 小时资源预算内。

建议成功标准：

- 至少 2/3 seeds 的 final CE 优于各自 M0
- 报告均值、标准差和 paired episode bootstrap CI
- 不以最优 seed 代替总体结论

### P2：补齐分项评测

把 aggregate CE 分解为：

- SET / OVERWRITE / CLEAR / NOOP
- query 距离最近 updater 的 turn gap
- 一个 episode 内经历的 updater 数量
- terminal NOOP 的 QA 与 identity 两部分
- 不同 diffusion selected step

这能判断改善来自真正的覆盖/清除记忆，还是主要来自简单 SET 或短距离查询。

### P3：梯度归因与稳定性消融

先增加诊断，不立即提高 rank：

1. 记录每个 micro-transition 的未裁剪梯度范数，而不仅是 8 个 micro 累积后的 step norm。
2. 分别记录 QA loss、identity loss 对 LoRA 的梯度范数。
3. 按 event kind、selected diffusion step、prefix replay 长度定位尖峰。
4. 在相同初始权重上做短预算 matched arms：
   - 当前 LR=3e-5、clip=1.0
   - LR=1e-5、clip=1.0
   - 当前 LR + adaptive/percentile clipping

比较 fixed endpoint CE、clip 触发率和更新方向一致性。当前 98.4% 的 step 都被 clip，说明单纯增加步数并非第一优先级。

### P4：满足因果性与复现门槛后再扩大预算

如果 P0 视觉因果对照为正、P1 至少 2/3 seeds 改善，再考虑 512 或约 640 steps。按本次吞吐，640 steps 的训练段约 2.95 小时，连同启动/final eval 可控制在 3–4 小时内。扩大预算时仍应使用 fixed endpoint，不按中间 dev 选 checkpoint。

## 九、最终判断

本次实验成功解决了此前“DreamLite 主线无法稳定训练”的核心阻塞：它不是只能靠调几个参数碰运气，也不需要退回纯文本 Qwen baseline。R4-FreePixel 通过改变梯度路径、因果局部目标和状态生命周期，使 DreamLite 主线真正具备了完整可训练性。

下一步不应立刻加入 canonical teacher、把像素变成人类可读 ledger，或用更多参数掩盖问题。最有信息量的路线是：**先做视觉状态因果对照 → 两个额外种子复现 → 梯度归因与稳定性消融 → 再扩大到 3–4 小时预算**。
